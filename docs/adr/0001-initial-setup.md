# ADR-0001: Clean Architecture + PostgreSQL без ORM

Статус: accepted
Дата: 2026-08-19

## Контекст

Стартуємо trip-ledger — API поїздок і витрат. Треба обрати архітектурний патерн і спосіб роботи з БД до першого рядка коду.

## Рішення

1. **Clean Architecture, а не Layered.** У домені є справжні бізнес-правила (життєвий цикл поїздки, заборона витрат у закритій поїздці, підсумки по категоріях) — хочу тестувати їх без БД і Express. Layered для цього замалий: у ньому domain-правила розповзаються по сервісах і контролерах. Hexagonal не беру — transport один (REST), окремі in/out порти на 5 ендпоінтів були б передчасною оптимізацією.
2. **PostgreSQL через `pg` + SQL-міграції, без ORM.** Схема маленька (2 таблиці), запити прості. ORM (Prisma/TypeORM) тягне свій рантайм і провокує протікання моделей БД у domain. Репозиторії пишуться руками під інтерфейси з domain.
3. **TypeScript не enforce-ить dependency rule** — правило зафіксоване в CLAUDE.md і перевірятиметься eslint-правилом import/no-restricted-paths (додамо разом з першою фічею).

## Наслідки

- (+) Domain тестується чистими юніт-тестами, зміна БД не чіпає бізнес-логіку.
- (+) Claude при генерації коду має явні заборони імпортів.
- (−) Більше файлів на просту фічу, ніж у Layered — свідома ціна.
- (−) Без ORM руками пишемо мапінг рядків БД у сутності.
