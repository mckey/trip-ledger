# 0004 — Ввести знаковий value object `Balance` у `shared`, не послаблювати інваріант `Money`

- **Status:** Accepted
- **Date:** 2026-09-02
- **Deciders:** Vladimir Makarov (owner фічі, архітектор) — Socratic walk `architecture-design`

## Контекст

AC-03b: якщо counted expenses перевищили budget, remaining показується від'ємним числом, «а не нулем і не приховується». Але `src/shared/Money.ts` за конструктором відкидає від'ємні суми (`amount < 0` → помилка) — це інваріант, на який спираються `Expense` і майбутній budget. Отже, remaining через `Money` виразити неможливо (Explore §f), і треба вирішити, яким типом він їздить від `BudgetBlock` до відповіді.

Масштаб удару: `shared/` бачать **обидва BC**, зміна інваріанту `Money` зачепила б усі місця, де він конструюється; є **чесні альтернативи**. 2 з 3 → ADR.

## Драйвери рішення

- PRD §6 NFR «Точність грошей»: 0 похибки округлення — суми у minor units (integer), без плаваючої точки.
- PRD §5 AC-03b: від'ємний remaining показується від'ємним.
- CLAUDE.md: `shared/` — спільні value objects без бізнес-логіки контекстів; `Money` вже там.
- sad.md §1 QG-3: витрата й budget не можуть бути від'ємними — цей інваріант має лишитись у типі, а не переїхати у zod-схеми.

## Розглянуті варіанти

1. **Новий value object `Balance` у `shared/`**: знакове ціле у мінорних одиницях + валюта; `Balance.of(money)`, `minus(money)` з перевіркою валюти, `isNegative()`. `Money` лишається невід'ємним для сум і budget.
2. **Послабити `Money`** — дозволити від'ємний `amount`. Найменший diff, але тоді `new Expense(..., new Money(-500, 'EUR'))` стає конструйованим, і єдиним захистом лишається zod на HTTP-межі; доменний інваріант «сума витрати невід'ємна» зникає з типу.
3. **Без value object** — `remaining: number` (знакові мінорні одиниці) у DTO, арифметика прямо в `BudgetBlock`. Мінімум коду, але валюта їздить окремим полем, і перевірку «та сама валюта» доводиться повторювати в кожному місці, де remaining рахується чи порівнюється.

## Результат рішення

**Обрано:** Варіант 1 — окремий `Balance` у `shared/`.

**Чому переміг:** зберігає інваріант `Money` там, де він захищає домен (витрати, budget), і дає remaining власний тип із власними правилами (знак дозволений, валюта одна, лише цілі). Арифметика централізована й property-тестується — прямий шлях до QG-1. `shared/` при цьому лишається без бізнес-логіки: `Balance` не знає ні про поїздки, ні про бюджети.

## Наслідки

**Позитивні:**
- `Money` та його споживачі не змінюються; від'ємна витрата лишається неможливою на рівні типу.
- Remaining має явний тип із `isNegative()` — overspend signal читається з нього без магічних порівнянь.
- `Balance.test.ts` покриває цілочислову арифметику property-тестом (QG-1 «0 похибки округлення»).

**Негативні:**
- Два схожі value object-и у `shared/` — треба пам'ятати, що `Money` для сум, `Balance` для різниць.
- Ще один тип, який має правильно серіалізуватись у presentation (`{ amount, currency }` зі знаком).

**Нейтральні:**
- Коли multi-currency-summary додасть converted total, він теж виражається `Balance`/`Money` у мінорних одиницях — округлення до цілого лишається єдиною точкою (її правило — окреме рішення тієї фічі).
